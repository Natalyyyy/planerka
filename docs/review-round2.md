# Второй круг ревью

Исправлены все четыре пункта Высокая/Средняя из второго отчёта. В нём нет пунктов, прямо отмеченных ревьюером как продуктовое решение владельца.

1. Callback допускается только при совпадении `from.id` и `message.chat.id` с настроенным положительным `chat_id`. Чужие, неполные и групповые callback не меняют решения.
2. Старый маркер дедлайна получает версию прежнего банка без повторной генерации или повторного уведомления о завершённом дедлайне. Пересобранный банк с UUID и новый срок обрабатываются отдельно. Ошибка записи миграции не запускает модель.
3. Журнал отправки без версии больше не подавляет досылку: отправляются новые кнопки с неделей и версией. Последующие досылки используют обновлённый журнал.
4. Ошибка чтения уже записанного плана не запускает модель заново: сохраняется завершённая сборка и отправляется уведомление с предложением открыть файл.

## TDD и результат

До правок кода сохранены воспроизводящие падения: `review-red/round2-1.log` … `round2-4.log`. Добавлено 15 тестовых случаев. Существующие проверки не удалены и не ослаблены: валидные callback в прежних фикстурах дополнены полями Telegram, актуальный журнал — версией банка.

Смоделировано применение действия внешним сервисом с потерей ответа: подтверждение callback, отправка кнопок и уведомления. Повторное нажатие идемпотентно; готовый план не генерируется заново. При потере ответа Telegram сообщение может прийти повторно — API отправки не даёт гарантии exactly-once.

Полный прогон: `/opt/homebrew/bin/python3 -m pytest -q --tb=short` (установленный Python 3.14, зависимости не менялись).

```text
1 failed, 506 passed, 4 warnings in 4.44s
```

Единственное падение прежнее: `test_старый_лок_живого_но_чужого_pid_считается_устаревшим`. Песочница запрещает `/bin/ps` (`Operation not permitted`); тест сохранён без изменения. Полный вывод: `review-round2-full.log`. Все 15 новых случаев прошли.

Логи обоих кругов очищены от персональных абсолютных путей. Сеть, секреты, коммиты и push не использовались.
